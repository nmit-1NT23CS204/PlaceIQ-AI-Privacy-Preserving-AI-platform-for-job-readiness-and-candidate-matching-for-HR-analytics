1. Product Vision & Goals



PlaceIQ AI replaces manual, guesswork-driven campus placement with a continuously learning AI system that understands every student holistically, predicts their career readiness, and matches them to roles with data-backed precision and full explainability.



1.1  Product Vision Statement

Vision:  To be the most intelligent campus placement platform that gives every student a personalised, data-driven path to their first job — while giving colleges and recruiters the precision analytics they need to make faster, fairer, and better placement decisions.



1.2  Business Goals

5. Recommended Tech Stack with Justification



Every technology choice is driven by three constraints: (1) a student team with limited time, (2) a pretrained-model-first AI approach to avoid training from scratch, and (3) a cloud-deployable prototype demonstrable within Semester VI.



5.1  Tech Stack at a Glance

Frontend:  React.js 18 + Redux Toolkit + Tailwind CSS + Recharts

Backend:  Node.js 20 + Express.js + Bull (job queues) + Redis

Auth:  JSON Web Tokens (JWT) + bcrypt + RBAC middleware

Database:  MongoDB Atlas (primary) + Redis (cache/queues) + AWS S3 (files)

AI / ML:  Python FastAPI + Hugging Face Transformers (Sentence-BERT) + XGBoost + scikit-learn

Deployment:  AWS EC2 + S3 + CloudFront + MongoDB Atlas + Docker + Jenkins CI/CD



5.2  Detailed Justification



Layer

Choice

Justification

Frontend

React.js 18

Component-driven architecture maps perfectly to PlaceIQ's three distinct portals (Student, TPO, Recruiter). React's virtual DOM ensures fast re-renders when AI result data updates. Massive ecosystem (Redux, Recharts, React Router) covers every UI need. Team familiarity with React reduces learning curve in a time-constrained semester.

State Mgmt

Redux Toolkit

Auth tokens, AI score results, and drive state must persist across multiple pages without prop drilling. Redux Toolkit's modern slice pattern is far less boilerplate than classic Redux and integrates cleanly with React 18 concurrent features.

Styling

Tailwind CSS

Utility-first CSS eliminates writing custom CSS files for every component. Produces consistent, responsive layouts rapidly — critical when four developers need to build UIs in parallel without style conflicts. No design system setup needed.

Charts

Recharts

Native React charting library — no separate chart DOM to manage. Provides radar charts (skill profile), bar charts (gap analysis), line charts (readiness trend), and doughnut charts (analytics) all in one library with clean, minimal default styling.

Backend

Node.js + Express

JavaScript on both frontend and backend means the full-stack developers use one language across the entire application. Express.js's middleware-first architecture is ideal for layering JWT auth, RBAC, rate limiting, and input validation. Node's async I/O handles concurrent resume uploads and API calls efficiently.

Job Queues

Bull + Redis

Resume embedding and score computation are slow (2–5s). Running them synchronously would block the API response. Bull queues these as background jobs, decoupling the user-facing API from the AI processing pipeline. Redis backs the queue and also caches frequently-read score results.

Auth

JWT + bcrypt

Stateless JWT tokens are ideal for a multi-portal app where React, Node, and Python services all need to validate identity without shared server state. bcrypt provides industry-standard password hashing. Custom RBAC middleware on Express enforces role boundaries (student vs TPO vs recruiter) at the route level.

Database

MongoDB Atlas

Resume data, skill profiles, embedding vectors, and drive records all have variable, nested structures that don't fit cleanly into SQL schemas. MongoDB's document model accommodates this naturally. Atlas provides managed cloud hosting with built-in encryption, automated backups, and Atlas Search for full-text queries — all without DBA effort.

File Storage

AWS S3

Resume PDFs must be stored outside the database (binary blobs degrade MongoDB performance). S3 provides scalable, secure object storage with pre-signed URLs for direct access control. AWS IAM policies ensure only the backend service can read student files.

AI Service

Python FastAPI

Python is the undisputed language of AI/ML — Hugging Face, XGBoost, and scikit-learn all have first-class Python support. FastAPI is async, auto-documents endpoints via OpenAPI, and starts in < 3 seconds. Separation from Node.js means AI engineers work in their native environment without touching the web stack.

NLP Model

Hugging Face Sentence-BERT (all-MiniLM-L6-v2)

Using a pretrained model eliminates training from scratch — critical given the semester time constraint. all-MiniLM-L6-v2 is the industry standard for semantic sentence similarity: 384-dim output, < 80 MB download, runs on CPU in < 200ms per document, and produces state-of-the-art semantic matching quality for skill and JD comparison tasks.

ML Model

XGBoost

Gradient-boosted trees outperform logistic regression on tabular feature vectors (CGPA, coding score, embedding PCA, backlogs) with limited training data. XGBoost trains in seconds on 500-row mock datasets, produces calibrated probabilities, and can be serialised to a 50 KB .pkl file for fast FastAPI inference.

Explainability

SHAP / Rule engine

SHAP provides mathematically rigorous feature attribution for the XGBoost model. For the Semester VI PoC, a lightweight rule-based label engine (top-2 feature names from feature_weights dict) produces readable explanations without the full SHAP overhead. Full SHAP integration is the Semester VII upgrade.

Containers

Docker

Docker ensures that the Node.js API and Python FastAPI service run identically on every developer's machine, in the Jenkins CI environment, and on AWS EC2. Eliminates 'works on my machine' problems. docker-compose.yml defines the full local stack in one file.

CI/CD

Jenkins + GitHub

Jenkins integrates natively with GitHub webhooks. Every push to the main branch automatically triggers: lint → unit tests → Docker build → image push to AWS ECR → deploy to EC2. The Jenkinsfile lives in the repo for full auditability. Blue-green deployment ensures zero-downtime PoC demos.

Cloud

AWS EC2 + CloudFront

EC2 t3.medium hosts both Docker containers within budget for a student PoC. CloudFront CDN serves the React build with < 100ms latency globally. AWS services integrate natively (S3, IAM, ACM for TLS) without multi-vendor complexity.

7. Constraints & Assumptions





7.1  Constraints

Constraint Type

Description

Time

Semester VI prototype must be demo-ready within 20 weeks. Full production features deferred to Semester VII.

Team Size

4 developers (2 full-stack, 2 AI/ML). No dedicated DevOps, Designer, or QA engineer.

Budget

AWS Free Tier + Atlas M0 free cluster for development. EC2 t3.medium (~$30/month) for demo deployment.

AI Models

No custom model training from scratch. Only pretrained models from Hugging Face are used in v1.0.

Data

No real institutional student data available for training. Synthetic mock data (500 records) used for ML model training.

Security

Basic security measures (JWT, bcrypt, HTTPS, S3 encryption) implemented. Full pen-testing and compliance audit deferred to v2.0.

Audio Processing

Audio interview feedback transcription (Whisper) is out of scope for v1.0. Text-only feedback accepted.



7.2  Assumptions

Students have a professional resume in PDF or DOCX format available for upload.

The college has a designated TPO officer who will manage drives and enter outcome data.

Recruiters are willing to submit a plain-text job description to the system.

The institution can provide basic academic record data (CGPA, backlogs) for the student profiles.

AWS Free Tier and MongoDB Atlas M0 are sufficient for the Semester VI demo with up to 100 concurrent test users.

The Hugging Face all-MiniLM-L6-v2 model produces acceptable semantic similarity quality without domain fine-tuning for the PoC.

Internet connectivity is available at the demo venue for the live AWS deployment demonstration.

9. Glossary





Term

Definition

MERN Stack

MongoDB, Express.js, React.js, Node.js — the full JavaScript web development stack used for PlaceIQ AI.

BERT / Sentence-BERT

Bidirectional Encoder Representations from Transformers — a pretrained NLP model that encodes text as dense semantic vectors. Sentence-BERT is a variant optimised for sentence-level similarity.

Embedding

A dense numerical vector (array of floats) that represents text semantically. Similar texts have similar embeddings (high cosine similarity).

Cosine Similarity

A metric measuring the angle between two vectors. Score of 1.0 = identical direction (perfect match); 0.0 = no similarity.

XGBoost

Extreme Gradient Boosting — a high-performance gradient-boosted decision tree algorithm used for PlaceIQ's readiness score prediction.

JWT (JSON Web Token)

A compact, signed token used to authenticate users across stateless API requests. Contains user ID and role encoded and signed.

RBAC

Role-Based Access Control — a security model that grants permissions based on user role (student, TPO, recruiter, admin).

Bull

A Node.js library for creating and managing Redis-backed background job queues. Used for async AI inference triggers.

SHAP

SHapley Additive exPlanations — a method to explain ML model predictions by attributing each feature's contribution to the output.

RL Agent

Reinforcement Learning Agent — an AI component that learns a matching policy by receiving reward signals (placement outcomes) and updating its decision strategy over time.

TPO

Training & Placement Officer — the college staff member responsible for managing campus placements.

FastAPI

A modern, high-performance Python web framework for building APIs with automatic OpenAPI documentation.

CI/CD

Continuous Integration / Continuous Deployment — automated pipeline that builds, tests, and deploys code on every commit.
